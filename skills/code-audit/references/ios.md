# iOS variant checklist

Standards: OWASP MASVS v2 + MASTG, OWASP Mobile Top 10 (2024), Apple security guidance (App Store Review, ATS, Keychain, Data Protection), `PrivacyInfo.xcprivacy` / entitlements hygiene, Swift/Objective-C best practices, Apple HIG accessibility (WCAG-aligned).
Cover Swift, Objective-C, SwiftUI/UIKit, Xcode project settings (`project.pbxproj`, `*.xcconfig`), `Info.plist`, `*.entitlements`, `PrivacyInfo.xcprivacy`, `Package.swift`/`Package.resolved`/`Podfile(.lock)`/`Cartfile`, extensions (widgets, share, notification service), and Fastlane/CI files.

Level gating: **l1** = (1). **l2** = (1)+(2). **l3** = all incl. (3) resilience.

## A. Security & Auth/Crypto

**Keychain & storage (MASVS-STORAGE-1/2, MASVS-CRYPTO, M9/M1)**
- (1) Secrets/tokens/PII in `UserDefaults`, plist, Core Data/SQLite/Realm unencrypted, files in `Documents`/`Library/Caches`/`tmp` without `FileProtectionType`, pasteboard (`UIPasteboard.general` with secrets; use `.setItems(options: [.localOnly, .expirationDate])`), logs (`print`, `NSLog`, `os_log` with `%{public}` on sensitive data, `debugPrint`), crash/analytics payloads, `UIWebView`/`WKWebView` cache, snapshots (no obscuring in `applicationWillResignActive`/`sceneWillResignActive`: app switcher screenshot) -> MASVS-STORAGE-2/PLATFORM-3.
- (1) Keychain usage: `kSecAttrAccessible` values: `kSecAttrAccessibleAlways`/`AlwaysThisDeviceOnly` (deprecated/insecure), `AfterFirstUnlock` for highly sensitive items (prefer `WhenUnlockedThisDeviceOnly` / `WhenPasscodeSetThisDeviceOnly`); missing `ThisDeviceOnly` for items that must not sync via iCloud Keychain/backup; `kSecAttrSynchronizable` true on secrets; `SecAccessControl` with `.biometryCurrentSet`/`.userPresence` for high-value items; Keychain items not deleted on logout/first launch after reinstall (stale across reinstall); shared keychain access groups too broad; ignoring `OSStatus` return codes (silent failure -> fallback to insecure storage).
- (1) Backup/data protection: files containing sensitive data not marked `isExcludedFromBackup`/`.completeFileProtection`; `NSFileProtectionNone`; Core Data store options lacking protection.
- (1) Hardcoded secrets/API keys/private keys/tokens in source, `Info.plist`, `.xcconfig`, `GoogleService-Info.plist` (note Firebase keys are identifiers, not secrets, but unrestricted usage/open rules matter: Needs Verification), `Config.plist`, assets, embedded `.p12`/`.pem`, Fastlane `Appfile`/`Matchfile`; strings readable in binary (MASVS-CRYPTO-2/M1).

**Crypto (MASVS-CRYPTO-1/2, M10)**
- (1) `CommonCrypto`: `kCCAlgorithmDES`/`3DES`/`RC4`, `kCCOptionECBMode`, MD5 (`CC_MD5`, `Insecure.MD5`), SHA-1 for security; static/zero IV; hardcoded key/salt; `arc4random`-free token generation (`rand()`, `random()`, `Int.random` ok for non-security only; for secrets use `SecRandomCopyBytes`/`SystemRandomNumberGenerator`/CryptoKit); low PBKDF2 iterations; RSA PKCS1 v1.5 encryption; custom crypto; CryptoKit nonce reuse with `AES.GCM`; keys stored outside Keychain/Secure Enclave (`kSecAttrTokenIDSecureEnclave` for high-value keys).

**Network & TLS (MASVS-NETWORK-1/2, M5)**
- (1) ATS: `NSAppTransportSecurity` -> `NSAllowsArbitraryLoads` = true (or `NSAllowsArbitraryLoadsInWebContent`/`ForMedia`/`LocalNetworking` broadening), per-domain `NSExceptionAllowsInsecureHTTPLoads`, `NSExceptionMinimumTLSVersion` < 1.2, `NSTemporaryException*`; App Store justification required for exceptions. `http://` URLs in code/config.
- (1) TLS validation bypass: `URLSessionDelegate` `urlSession(_:didReceive:completionHandler:)` that unconditionally calls `.useCredential` with `URLCredential(trust:)`; `.performDefaultHandling` skipped; `NSURLRequest.allowsAnyHTTPSCertificate`/`setAllowsAnyHTTPSCertificate`; Alamofire `DisabledTrustEvaluator`/`ServerTrustManager` with `evaluators: [:]` & `allHostsMustBeEvaluated: false`; `SecTrustSetExceptions` misuse; `kCFStreamSSLValidatesCertificateChain = false`; `SSLSetSessionOption(...kSSLSessionOptionBreakOnServerAuth)`; custom pinning that only pins on success path and falls through on failure; `NSPinnedDomains` in Info.plist (preferred) or TrustKit config (check enforcement and backup pins) (2). Pin-bypass resilience: Needs Verification (MASTG dynamic: objection/Frida).
- (2) Sensitive data in URL query strings, `URLCache`/cookie storage retaining auth responses (`URLSessionConfiguration.ephemeral` for sensitive sessions), `HTTPCookieStorage` persistence of session cookies, `waitsForConnectivity`/retries replaying non-idempotent POSTs.

**Authentication (MASVS-AUTH, M3)**
- (1) Local auth as boolean-only: `LAContext.evaluatePolicy` result used to gate UI without Keychain item protected by `SecAccessControl` (bypassable with Frida: Needs Verification); `.deviceOwnerAuthentication` vs `.deviceOwnerAuthenticationWithBiometrics` semantic mismatch; fallback weakness; `evaluatedPolicyDomainState` not checked for enrollment changes (2); tokens persisted indefinitely; refresh-token races (single-flight); logout not clearing Keychain/cookies/caches/`WKWebsiteDataStore`; OAuth via embedded `WKWebView` instead of `ASWebAuthenticationSession`; custom URL scheme as OAuth redirect (hijackable; prefer Universal Link + PKCE); Sign in with Apple handling/credential-state check (`getCredentialState`) (2).

**IPC & platform (MASVS-PLATFORM-1/2/3, M4/M8)**
- (1) URL schemes: `CFBundleURLTypes` custom schemes: handler (`application(_:open:options:)`, `scene(_:openURLContexts:)`, `onOpenURL`) parses host/path/query w/o validation, allows unauthenticated state change, triggers navigation/WebView load/file access, leaks token via `options[.sourceApplication]` trust; scheme squatting risk for auth callbacks. Universal Links: `applinks:` in entitlements, `apple-app-site-association` pairing (server-side: Needs Verification), `NSUserActivity` `webpageURL` host/path validation (host check using `hasSuffix` bypassable), `continueUserActivity` handlers trusting params, open redirect into WebView.
- (1) `WKWebView`: `javaScriptEnabled` w/ remote/untrusted content; `WKScriptMessageHandler`/`add(_:name:)` exposing native actions (payments, file, keychain) without origin check (`message.frameInfo.securityOrigin`/`isMainFrame`) or input validation; `WKNavigationDelegate.decidePolicyFor` absent or `.allow` always; `loadFileURL(_:allowingReadAccessTo:)` with broad read root; `allowFileAccessFromFileURLs`/`allowUniversalAccessFromFileURLs` via KVC; `evaluateJavaScript` with string-concatenated user data (JS injection: use `callAsyncJavaScript` args/JSON encoding); `isInspectable = true` (iOS 16.4+) in release; `UIWebView` presence (removed/rejected); `SFSafariViewController` vs WKWebView for auth; `WKWebsiteDataStore` persistence of auth; `javaScriptCanOpenWindowsAutomatically`; custom `WKURLSchemeHandler` path traversal.
- (1) Extensions/Shared containers: App Group data readable by extensions w/o protection; Share/Action extension accepting untrusted items without validation; `UIActivityViewController` leaking data to other apps; `UIPasteboard`; `UIDocumentPicker`/`openURL` handling imported files (copy to sandbox, validate type/size, path-traversal in unzip); URL `canOpenURL` queries (`LSApplicationQueriesSchemes` over-broad = fingerprinting); keyboard extension (disable for secure fields: `isSecureTextEntry`, `textContentType`); `UIApplicationShortcutItem`/Siri intents/App Intents exposing sensitive actions without auth; push notification payload processing (`userInfo` trusted; sensitive content in notification text; Notification Service Extension handling secrets).
- (2) Screen protection: no obscuring of sensitive screens on backgrounding/screenshot/recording (`UIScreen.capturedDidChangeNotification`, `isCaptured`); `UITextField` secure entry/`autocorrectionType = .no` on secrets; `UIApplication.shared.isIdleTimerDisabled` misuse; `UIPasteboard` autopaste; Handoff (`NSUserActivityTypes`, `isEligibleForHandoff`) exposing data.

**Input validation / injection (MASVS-CODE-4)**
- (1) SQLite (`sqlite3_exec` w/ string format, GRDB/FMDB string interpolation instead of bound params), Core Data `NSPredicate(format:)` with `%@`-less user concatenation, `NSExpression` injection, format-string bugs (`String(format: userString)`, `NSLog(userString)`), `NSKeyedUnarchiver.unarchiveObject(with:)`/`unarchiveTopLevelObjectWithData` without `requiresSecureCoding`/`NSSecureCoding` (use `unarchivedObject(ofClass:from:)`), `NSCoding` object injection, `JSONSerialization` -> force cast crash, `XMLParser`/`NSXMLParser` entity expansion (`shouldResolveExternalEntities`), `dlopen`/`NSClassFromString` on external names, `system()`/`posix_spawn` (non-jailbreak irrelevant but flag if present), `NSTask` in macOS targets, `String(contentsOfFile:)` with user paths (traversal), zip extraction (zip-slip).
- (2) Objective-C/C interop: `strcpy/sprintf/memcpy/gets`, unchecked buffer sizes, integer overflow on `malloc(count * size)`, `UnsafePointer`/`withUnsafeBytes` out-of-bounds, use-after-free via `Unmanaged`/`passUnretained`, `bridge_transfer` leaks/double free, ARC bridging mistakes.

**Resilience (MASVS-RESILIENCE, M7)**: (3) Jailbreak/debugger/hooking/tamper detection absent or trivially bypassable (file-existence checks only), no `PT_DENY_ATTACH`/sysctl debugger checks, no code-signing/integrity validation, DeviceCheck/App Attest not verified **server-side**, symbols not stripped (`STRIP_INSTALLED_PRODUCT`, `DEPLOYMENT_POSTPROCESSING`), `GCC_GENERATE_DEBUGGING_SYMBOLS`, sensitive strings/URLs plain in binary, ObjC class/method names exposing logic. Report only if the threat model requires; effectiveness = Needs Verification (MASTG-RESILIENCE).

**Release & binary hardening (MASVS-CODE-3, MASVS-RESILIENCE; checked at l1/l2 for build settings, l3 for runtime resilience)**
- (1) Release configuration keeps debug artifacts: `STRIP_INSTALLED_PRODUCT = NO`, `COPY_PHASE_STRIP = NO`, `STRIP_STYLE` not `all`/`non-global`, `DEPLOYMENT_POSTPROCESSING = NO`, `DEBUG_INFORMATION_FORMAT = dwarf` (should be `dwarf-with-dsym` with dSYMs uploaded privately, not shipped), `GCC_OPTIMIZATION_LEVEL=0`/`SWIFT_OPTIMIZATION_LEVEL=-Onone` in Release, `ENABLE_TESTABILITY=YES` in Release, `-fno-stack-protector`/PIE disabled (`GCC_GENERATE_POSITION_DEPENDENT_CODE`), ARC disabled (`-fno-objc-arc`) on security code.
- (2) Release-only integrity: App Attest (`DCAppAttestService`)/DeviceCheck used but assertion/receipt **not verified server-side** (client-only check is bypassable: Needs Verification); no minimum-OS/outdated-version enforcement path; jailbreak/tamper checks only via file-exists (weak) where risk warrants; sensitive logic in Objective-C with readable selectors (consider Swift/obfuscation) at l3.

**Certificate pinning strategy (MASVS-NETWORK-2)**
- (2) If pinning exists, verify a **safe rotation strategy**: pin to SPKI hash of an intermediate/CA or include backup pins (>= 1 pin not in current chain), pin set expiry/remote-config kill-switch, `NSPinnedDomains` with `NSIncludesSubdomains` scope reviewed, failure path fails closed but reports telemetry, no leaf-only pinning that bricks the app at renewal. Pinning absent on high-risk (finance/health) app = Medium at l2/l3, Info at l1.

## B. Code Quality, Concurrency & Logic (MASVS-CODE)

- (1) Crashes: force unwrap `!` / `try!` / `as!` / `fatalError`/`precondition`/`preconditionFailure`/array index without bounds check on externally-sourced data (network JSON, deep link params, push payload, file contents, user input); implicitly unwrapped optionals (`var x: T!`) set late (IBOutlets are common noise: don't flag outlets); unchecked `URL(string:)!`; `Decodable` w/ required keys for optional server fields; `Int` overflow on untrusted arithmetic (trap); `DispatchQueue.main.sync` from main (deadlock).
- (1) Retain cycles/memory: closures capturing `self` strongly in stored/long-lived callbacks (Combine `sink`, `NotificationCenter` block observers, timers `Timer.scheduledTimer`, `URLSession` completion stored on self, `DispatchSource`, delegates declared non-`weak` -> `weak var delegate`), `[weak self]`/`[unowned self]` misuse (unowned crash after dealloc), `AnyCancellable` not stored/leaked, KVO/NotificationCenter observers not removed (pre-iOS 9 targets), `CADisplayLink`/`Timer` strong target, large image caches without eviction, `Task` capturing self indefinitely, SwiftUI `@StateObject` vs `@ObservedObject` recreation bugs, `Combine` subscriptions never cancelled.
- (1) Concurrency: UI updates off the main thread (UIKit calls from background closures; missing `@MainActor`); data races on shared mutable state (global/static vars, class properties accessed from multiple queues/Tasks) w/o actor/serial queue/lock; Swift 6 strict-concurrency: non-`Sendable` types crossing isolation (`@unchecked Sendable` hiding races), `nonisolated(unsafe)`, `Task.detached` capturing non-Sendable, actor reentrancy bugs (state assumed unchanged across `await`), missing `Task` cancellation checks (`Task.checkCancellation`, `try Task.sleep` handling), unstructured `Task {}` fire-and-forget losing errors, `DispatchSemaphore`/`.wait()` blocking cooperative pool (deadlock/priority inversion), `async let` misuse; GCD: concurrent queue + `.barrier` misuse, `sync` on same queue deadlocks; Core Data contexts used across threads (`perform`/`performAndWait` not used); token-refresh single-flight race; double-tap/duplicate network submission without idempotency.
- (1) Error handling: empty `catch {}`, `try?` swallowing meaningful errors (esp. Keychain, crypto, file writes, auth), ignoring `Result.failure`, `completionHandler` not called on all paths (hangs/leaks), `NSError` ignored, `guard` falling through silently to insecure default, fail-open on auth/entitlement/jailbreak check errors.
- (2) Logic: client-only entitlements/receipt checks (StoreKit: verify transactions via `Transaction.currentEntitlements`/server validation; trusting local flags in UserDefaults), trusting device clock for expiry, offline queue replays, state restoration leaking logged-out data, background task (`beginBackgroundTask`) not ended (watchdog kill), `BGTaskScheduler` handlers lacking expiration handler, race between logout and in-flight requests repopulating storage, locale/timezone/number-format errors in money (use `Decimal`, not `Double`).
- (2) Complexity/dead code: massive view controllers (> ~600 lines), business logic in views, commented-out code, unused entitlements/permissions/classes, duplicated networking/crypto helpers, `#if DEBUG` blocks that disable security checks and could leak into release via wrong build settings (verify `SWIFT_ACTIVE_COMPILATION_CONDITIONS` per configuration), feature flags bypassing auth.

## C. Dependencies, Config & Supply Chain (M2, M8, SSDF)

- (1) Dependencies: `Package.swift` (`branch:`, `.revision`, `from:` too loose on security libs, local/`path:` deps), `Package.resolved` missing/uncommitted, `Podfile` unpinned/git branches, `Podfile.lock` missing, Cartfile `master`; abandoned or EOL libs (AFNetworking/old Alamofire, UIWebView-dependent SDKs, old OpenSSL/SQLCipher builds, JailMonkey-like stale libs); SDKs lacking `PrivacyInfo.xcprivacy`/signature (Apple-required "commonly used third-party SDK" list: state as Needs Verification); binary XCFramework deps without checksums (`checksum:`). Name CVEs only if certain; else recommend OSV-Scanner/`swift package audit`-equivalent/Dependabot.
- (1) Debug/config: `Info.plist`/build settings left for debugging: `get-task-allow` = true in release entitlements, `GCC_OPTIMIZATION_LEVEL = 0` in Release, `ENABLE_TESTABILITY = YES` in Release, `DEBUG_INFORMATION_FORMAT`/symbols shipped, `-ObjC`/`-all_load` bloat (info), `UIFileSharingEnabled`/`LSSupportsOpeningDocumentsInPlace` exposing Documents, verbose logging via `os_log` debug in release, staging/test endpoints and flags compiled into release, `#if targetEnvironment(simulator)` bypasses, hardcoded test credentials/backdoors, `NSAppleEventsUsageDescription` etc. unneeded, Reveal/FLEX/Netfox/Wormholy debug tools linked in release, `UIRequiredDeviceCapabilities`, minimum iOS target very old (< 15) widening surface.
- (2) Entitlements hygiene (`*.entitlements`): overbroad `com.apple.security.application-groups`, `keychain-access-groups` wildcards, `associated-domains` entries incl. unused/dev domains (`?mode=developer` left on), `aps-environment=development` in release, unneeded capabilities (HealthKit, HomeKit, Background Modes (`UIBackgroundModes`) not justified, `com.apple.developer.networking.*`), `com.apple.security.cs.allow-jit`/`disable-library-validation` on macOS/Catalyst targets, iCloud containers overly shared, `get-task-allow`.
- (2) CI/signing: signing certs/provisioning profiles/`.p12`/App Store Connect API keys/Fastlane `match` passwords in repo or CI logs, unpinned GitHub Actions/third-party scripts, `curl | sh`, distribution builds from unprotected branches, `CODE_SIGN_STYLE`/identity hardcoded to personal team.
- Logging/auditability (A09-equivalent): PII/tokens in `print`/`NSLog`/`os_log` (os_log default redacts dynamic strings as `<private>` unless `.public`), analytics/crash SDK user properties with PII, no security-event telemetry where backend support expected (Info).

## D. Accessibility & Platform Compliance

- (1) A11y (UIKit): custom controls/`UIView`+gesture recognizers without `isAccessibilityElement`/`accessibilityLabel`/`accessibilityTraits`; image buttons without labels; `accessibilityLabel` containing the trait word ("button"); decorative images exposed; text not using Dynamic Type (`UIFont.systemFont(ofSize:)` fixed, no `adjustsFontForContentSizeCategory`, `UIFontMetrics` absent) and truncating (`numberOfLines`, fixed heights); touch targets < 44x44pt; color as sole state indicator; `accessibilityViewIsModal` for custom overlays; focus/announcement (`UIAccessibility.post(notification:)`) after dynamic changes; respect Reduce Motion/Reduce Transparency/Bold Text/`prefersCrossFadeTransitions`; VoiceOver order via `accessibilityElements`.
- (1) A11y (SwiftUI): `Image` w/o `.accessibilityLabel` / `Image(decorative:)`; `onTapGesture` on non-Button views without `.accessibilityAddTraits(.isButton)`; `.font(.system(size:))` instead of text styles / `@ScaledMetric`; `.accessibilityHidden(true)` on meaningful content; combined elements via `.accessibilityElement(children: .combine)` missing; `.accessibilityInputLabels`, `accessibilityRepresentation` for custom controls. Contrast and VoiceOver real behavior -> Needs Verification (Accessibility Inspector).
- (2) **Apple HIG readiness:** system components/SF Symbols/semantic colors (`UIColor.label`, `Color.primary`) rather than hardcoded values (breaks Dark Mode, Increase Contrast); Dark Mode support (`overrideUserInterfaceStyle` forced without reason); safe-area/Dynamic Island/iPad multitasking layouts (fixed frames, `UIScreen.main.bounds` use); iPad/Split View/Stage Manager support when iPad is a target; localization (`NSLocalizedString`/String Catalogs, RTL via leading/trailing); standard navigation/back-swipe not disabled; haptics/animations honoring Reduce Motion; no loading/empty/error states.
- (2) **App Store Review Guidelines (cite section):** 2.1 app completeness (placeholder content, crash on launch/permission denial, debug menus/test accounts left in), 2.3 accurate metadata, 3.1.1 in-app purchase for digital goods (external payment links/StoreKit bypass), 4.8 Sign in with Apple when other social logins offered, 5.1.1 data collection/consent/purpose strings/account deletion (5.1.1(v)), 5.1.2 data use/sharing & ATT, 5.1.3 health data restrictions, 5.1.4 kids' apps/COPPA, 2.5.x software requirements (private APIs/`dlopen` of private frameworks, dynamic code download/`JSContext`/WebView-based remote logic changing app behavior, background mode misuse). Findings here are mostly Needs Verification (review is by Apple), Confirmed only when code plainly violates (e.g. private API symbol use, placeholder text).
- (2) **Regulatory (GDPR/CCPA/CPRA, HIPAA, COPPA):** analytics/ads/crash SDKs initialize before consent or ATT resolution; IDFA read without ATT authorization; PHI/PII unencrypted at rest (no `NSFileProtectionComplete`, plain Core Data), sent to third-party SDKs, or logged; no in-app deletion/export path; HIPAA-style audit logging and encryption in transit absent; data sharing not reflected in privacy manifest/nutrition label. Compliance conclusions are Needs Verification unless code plainly violates the rule.
- (2) Privacy & App Store compliance (MASVS-PRIVACY-1..4):
  - `PrivacyInfo.xcprivacy` present for app and each bundled third-party SDK; `NSPrivacyTracking`, `NSPrivacyTrackingDomains`, `NSPrivacyCollectedDataTypes` consistent with code (analytics/ads SDKs/IDFA/location/contacts usage); `NSPrivacyAccessedAPITypes` declares **required-reason APIs** actually used with valid reason codes: `UserDefaults` (CA92.1), file timestamp APIs (`creationDate`, `stat`, C617.1), system boot time (`systemUptime`, 35F9.1), disk space (`volumeAvailableCapacity…`, E174.1), active keyboard APIs (54BD.1). Flag usage without declaration (Needs Verification of exact reason codes against current Apple docs).
  - Usage description strings (`NSCameraUsageDescription`, `NSLocationWhenInUseUsageDescription`, `NSPhotoLibraryUsageDescription`, `NSContactsUsageDescription`, `NSMicrophoneUsageDescription`, `NSFaceIDUsageDescription`, `NSUserTrackingUsageDescription`, `NSBluetoothAlwaysUsageDescription`, etc.): missing for APIs used (crash on access), vague/unjustified text, present for unused APIs (review risk); `NSLocationAlways*` without need; ATT (`ATTrackingManager.requestTrackingAuthorization`) before IDFA use; account deletion in-app path (App Store requirement if account creation exists: Needs Verification); Sign in with Apple requirement when third-party login offered; encryption export compliance (`ITSAppUsesNonExemptEncryption`); `UIBackgroundModes` justification; HealthKit/Wallet/Push entitlement use matches code; Privacy Nutrition label consistency (Needs Verification).
