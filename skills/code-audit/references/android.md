# Android variant checklist

Standards: OWASP MASVS v2 + MASTG, OWASP Mobile Top 10 (2024), Google Play security/privacy/target-API requirements, Kotlin/Java/NDK best practices, Android Accessibility guidance (WCAG-aligned).
Cover Kotlin, Java, C/C++ (NDK), Gradle (Groovy/KTS), manifests, resources (`res/xml`, `res/values`), Compose and Views.

Level gating: **l1** = (1). **l2** = (1)+(2). **l3** = all incl. (3) resilience (MASVS-RESILIENCE) checks.

Always read first: every `AndroidManifest.xml` (incl. merged variants/flavors if present), `build.gradle(.kts)` (app + libs), `gradle/libs.versions.toml`, `proguard-rules.pro`, `res/xml/network_security_config.xml`, `res/xml/*backup*`/`data_extraction_rules.xml`, `res/xml/file_paths.xml`, `google-services.json`, `gradle.properties`, `local.properties` (must not be committed).

## A. Security & Auth/Crypto

**Manifest & components (MASVS-PLATFORM-1, M8/M3)**
- (1) `android:exported="true"` on activity/service/receiver/provider **without** `android:permission` (or with `<intent-filter>` forcing implicit export): trace what the component does with incoming `Intent` extras/data; targetSdk >= 31 requires explicit `exported` when filters exist.
- (1) `android:debuggable="true"` in release; `android:allowBackup="true"` (or default) with sensitive data and no `fullBackupContent`/`dataExtractionRules` exclusions (MASVS-STORAGE-2); `android:usesCleartextTraffic="true"`; `android:testOnly`.
- (1) Content providers: `exported`, `grantUriPermissions`, `path-permission`, SQL injection via `selection`/`projection`/`uri.lastPathSegment` concatenation, path traversal in `openFile` (`getCanonicalPath` check), FileProvider `file_paths.xml` exposing root/`.`/external broad paths.
- (1) Intent handling: untrusted `getIntent().getParcelableExtra`/`getStringExtra` used for navigation, file paths, URLs, or privileged actions; intent redirection (`startActivity(intent.getParcelableExtra("next"))`); `Intent.parseUri`/`getIntent().getData()` unvalidated; implicit intents carrying sensitive data (use explicit + `setPackage`); sticky broadcasts; dynamic `registerReceiver` without `RECEIVER_NOT_EXPORTED` (API 33+) or permission; `LocalBroadcastManager`/in-app Messenger alternatives.
- (1) `PendingIntent`: missing `FLAG_IMMUTABLE` (required targetSdk 31+) or `FLAG_MUTABLE` with empty/implicit base intent (hijack); explicit component set.
- (1) Deep links / App Links: `<intent-filter>` with `android:scheme` custom or `http` without `autoVerify="true"` and assetlinks; handler trusts host/path/query params (open redirect into WebView, parameter-driven auth state, token in URL); `BROWSABLE` exposure of sensitive activities; check `Uri` parsing (`getHost()` suffix checks bypass).
- (2) Task hijacking / tapjacking: `taskAffinity`/`launchMode` oddities on sensitive activities, `filterTouchesWhenObscured` absent on sensitive buttons (Login/Pay), `FLAG_SECURE` missing on sensitive screens (MASVS-PLATFORM-3: screenshots/recents), clipboard exposure of secrets, notification content on lock screen (`VISIBILITY_SECRET`).
- (2) Permissions hygiene (MASVS-PRIVACY-1/-3): dangerous permissions requested but unused (`READ_SMS`, `READ_CONTACTS`, `ACCESS_BACKGROUND_LOCATION`, `QUERY_ALL_PACKAGES`, `MANAGE_EXTERNAL_STORAGE`, `SYSTEM_ALERT_WINDOW`) -> Play policy risk; custom permissions with `protectionLevel` normal/dangerous guarding sensitive components -> use `signature`; runtime permission rationale/handling absent.

**WebView (MASVS-PLATFORM-2)**
- (1) `setJavaScriptEnabled(true)` + untrusted/remote content; `addJavascriptInterface` exposing methods without `@JavascriptInterface` care or to remote origins; `setAllowFileAccess(true)`, `setAllowFileAccessFromFileURLs`, `setAllowUniversalAccessFromFileURLs`, `setAllowContentAccess`; `loadUrl` with intent/deep-link-controlled URL without host allow-list; `shouldOverrideUrlLoading` returning false for everything; `onReceivedSslError` calling `handler.proceed()`; `WebView.setWebContentsDebuggingEnabled(true)` in release; mixed content `MIXED_CONTENT_ALWAYS_ALLOW`; Safe Browsing disabled; custom tabs vs WebView for auth (OAuth in WebView is a flag); no `WebViewAssetLoader` for local content.

**Storage & Keystore (MASVS-STORAGE-1/2, MASVS-CRYPTO, M9/M10)**
- (1) Sensitive data (tokens, passwords, PII, keys) in plain `SharedPreferences`, SQLite/Room unencrypted, files in `getExternalFilesDir`/public storage (`MODE_WORLD_READABLE/WRITEABLE`), cache dirs, logs (`Log.d/v/i` with PII/tokens; `HttpLoggingInterceptor.Level.BODY` in release), `printStackTrace`, crash reports (Crashlytics custom keys), clipboard, keyboard cache (`textNoSuggestions`/`TYPE_TEXT_VARIATION_PASSWORD`), screenshots.
- (1) Recommend/verify: Android Keystore-backed keys (`KeyGenParameterSpec`, `setUserAuthenticationRequired`, `setIsStrongBoxBacked` where available, `setInvalidatedByBiometricEnrollment`), `EncryptedSharedPreferences`/`EncryptedFile` (Jetpack Security Crypto is deprecated: prefer Keystore-backed AES-GCM + DataStore, or Tink; note rather than flag as vuln), SQLCipher with key from Keystore, not hardcoded.
- (1) Crypto misuse: `Cipher.getInstance("AES")` (defaults to ECB), `AES/ECB`, DES/3DES/RC4, MD5/SHA-1 for security, static/zero IV, IV reuse with GCM, `SecureRandom` seeded with constant, `java.util.Random`/`Math.random` for tokens, hardcoded keys/salts, PBKDF2 with low iterations, RSA without OAEP / `RSA/ECB/PKCS1Padding`, key in `BuildConfig`/`strings.xml`/`gradle.properties`.
- (2) Biometric/auth (MASVS-AUTH-2/3): `BiometricPrompt` used as boolean gate without a `CryptoObject` bound to Keystore key (bypassable with Frida: Needs Verification); fallback to weak PIN; no re-auth for sensitive operations; session token lifetime/refresh; token stored in prefs; logout not clearing data/keys; `setAllowedAuthenticators` too weak for risk level.

**Network (MASVS-NETWORK-1/2, M5)**
- (1) Cleartext `http://` URLs, `cleartextTrafficPermitted="true"` in `network_security_config.xml` (base-config or domains), `usesCleartextTraffic`; trusting user CAs in release (`<certificates src="user"/>` outside debug-overrides); custom `TrustManager` that accepts all, `HostnameVerifier { _, _ -> true }`, `SSLSocketFactory` w/ `ALLOW_ALL_HOSTNAME_VERIFIER`, OkHttp `.hostnameVerifier`/`.sslSocketFactory` overrides, TLS < 1.2, `SSLContext.getInstance("SSL"/"TLSv1")`.
- (2) Pinning absent for high-risk apps or misconfigured (`<pin-set>` without expiration/backup pin, OkHttp `CertificatePinner` with leaf only); pin bypass resilience = Needs Verification (MASTG dynamic). Sensitive data in URL query strings; unauthenticated analytics sending PII; API keys sent over non-TLS; Firebase DB/storage rules open (check `database.rules.json` if present).

**Injection / input validation (MASVS-CODE-4, M4)**
- (1) SQL via `rawQuery`/`execSQL` string concat (use bind args or Room); `Runtime.exec`/`ProcessBuilder` with input; reflection/`Class.forName` on external names; `DexClassLoader` loading from writable/external paths; zip entry path traversal (zip-slip) in extraction; unsafe deserialization (`Serializable`/`Parcelable` from intents with `readSerializable`, Java `ObjectInputStream`, Gson/Jackson polymorphic typing); XML parsers w/ external entities; format-string / `String.format` with user pattern.

**NDK/JNI (MASVS-CODE-4)**
- (2) Native code: `strcpy/strcat/sprintf/gets/memcpy` with unchecked lengths, integer overflow in size computations, missing bounds checks on `GetArrayLength`/`GetByteArrayRegion`, use-after-free of JNI global refs, local ref table leaks in loops, `NewStringUTF` on non-UTF8, unvalidated JNI input trusted, missing exception checks after JNI calls (`ExceptionCheck`), threads attached without detach, hardcoded secrets in `.so` strings, `-fstack-protector`/`_FORTIFY_SOURCE`/PIE/RELRO flags missing in `CMakeLists.txt`/`Android.mk`; vendored native libs outdated (libpng, openssl, ffmpeg).

**Resilience (MASVS-RESILIENCE, M7)**: only for **l3** or apps handling regulated/high-value assets; report as Medium/Low unless threat model requires:
- (3) R8/minify off in release; obfuscation absent on sensitive logic; root/emulator/debugger/hook detection absent or trivially bypassable; integrity (Play Integrity API) not verified **server-side**; no tamper detection of APK signature; secrets/URLs plain in resources; `FLAG_SECURE`; Needs Verification for effectiveness (MASTG-RESILIENCE dynamic tests).

## B. Code Quality, Concurrency & Logic (MASVS-CODE)

- (1) Lifecycle/memory leaks: Activity/Context/View held in singletons, companion objects, static fields, long-lived coroutines, `Handler` anonymous inner classes, listeners/receivers/observers not unregistered, `Fragment` view binding not nulled in `onDestroyView`, `AsyncTask` (deprecated) usage, `Bitmap` not recycled/large images loaded full-size; `GlobalScope.launch` / unstructured concurrency; `lifecycleScope`/`viewModelScope` misuse; `collect` on `Flow` in `lifecycleScope` without `repeatOnLifecycle`; `LiveData` observers with wrong owner.
- (1) Coroutines/concurrency: blocking calls (`runBlocking`, disk/network) on `Dispatchers.Main`; swallowed `CancellationException` (`catch (e: Exception)` without rethrow); shared mutable state across threads without `Mutex`/`Atomic`/confinement; `StateFlow`/`MutableStateFlow` read-modify-write races (use `update {}`); race between auth refresh requests (multiple 401s each refreshing token: use single-flight); double submission of payment/actions; DB transactions not used for multi-step writes.
- (1) Error handling: empty catch, `catch (Throwable)`, `!!` on nullable external data (NPE crash), `lateinit` uninitialized access, `as` unchecked casts on intent extras, `Intent.getXExtra` null deref, `onActivityResult` unchecked, ignoring `Result`/null returns, crashing on malformed server JSON (no defaults), `StrictMode` violations ignored; app-wide `UncaughtExceptionHandler` leaking data.
- (2) Logic: client-side-only authorization/price/entitlement checks (premium flags in prefs), trusting local time for expiry, license checks in client only, reliance on `Build.TAGS`/root checks as sole control, offline queue replays without idempotency, state restoration (`savedInstanceState`/process death) losing or leaking auth state, config-change duplication.
- (2) Complexity/dead code: god Activities/ViewModels (> ~500 lines), logic in UI layer, commented-out code, unused permissions/classes/resources (Lint `UnusedResources`), duplicated crypto helpers, debug/staging endpoints reachable in release.

## C. Dependencies, Config & Supply Chain (M2, M8, SSDF)

- (1) Gradle: `minSdk` very old (< 24) widening attack surface; `targetSdk` below current Play requirement (state requirement only if sure; otherwise Needs Verification); `compileSdk` stale; `isMinifyEnabled=false`/`isShrinkResources=false` in release (2); `isDebuggable=true` on release buildType; `signingConfigs` with hardcoded passwords/keystore path committed; keystore (`*.jks`) in repo; `buildConfigField` secrets; dynamic versions (`+`, `latest.release`), snapshot deps, `mavenLocal()`, untrusted repos, `http://` repositories, `allowInsecureProtocol = true`; no dependency verification/lock (`gradle/verification-metadata.xml`, `dependencyLocking`) (3); Gradle wrapper without `distributionSha256Sum` (3).
- (1) Libraries: flag known-EOL/abandoned (Jetpack Security Crypto deprecated, `AsyncTask`, old OkHttp/Retrofit/Glide majors, old `play-services` ads/analytics SDKs, support library). Name CVEs only if certain; otherwise recommend `./gradlew dependencyCheckAnalyze`/OSV-Scanner/Dependabot.
- (1) Hardcoded secrets in `strings.xml`, `google-services.json` API keys without restrictions (Needs Verification: API key restriction is server-side), `local.properties`, CI yaml, `.so` strings, `assets/`, `res/raw/`, Firebase config with open rules; third-party SDK keys (Maps, payments) with unrestricted scope.
- (2) R8/ProGuard: `-dontobfuscate`, `-keep class **` overly broad, `-keepattributes` leaking source names, `-dontwarn` hiding issues, rules removing logging stripped assumption (`-assumenosideeffects` for `Log` absent -> logs stay in release), keep rules required for reflection/serialization missing (runtime crash risk; Needs Verification).
- (2) CI: unpinned actions, signing keys in repo/CI logs, release built from unprotected branches, `debug` builds distributed.
- Logging/auditability: PII in Firebase Analytics/Crashlytics events/user properties; verbose logs in release (Timber `DebugTree` planted in release); no security-event logging for auth failures where backend support is expected (Info).

## D. Accessibility & Platform Compliance

- (1) A11y (Views): `ImageView`/`ImageButton` without `contentDescription` (or `importantForAccessibility="no"` for decorative) ; custom clickable views without `AccessibilityDelegate`/role; click handlers on non-button `View` w/o `setClickable`+description; `android:minHeight/minWidth` < 48dp touch targets; hardcoded `sp` -> `dp` text sizes blocking font scaling; `android:labelFor` for inputs; `textColor`/background hardcoded (contrast needs runtime check -> Needs Verification); `importantForAutofill`/`autofillHints` misuse; focus order via `accessibilityTraversalBefore/After`; `android:screenOrientation` locked w/o reason; Toasts as only error channel.
- (1) A11y (Compose): `Image`/`Icon` with `contentDescription = null` on meaningful content; `clickable` without `role`/`onClickLabel`; `Modifier.semantics` missing on custom controls; `minimumInteractiveComponentSize` disabled; `fontSize` hardcoded; `mergeDescendants` misuse; `testTag` used as only identifier.
- (2) Play compliance: Data safety form consistency (SDKs collecting data not declared: Needs Verification), `QUERY_ALL_PACKAGES`, background location, `MANAGE_EXTERNAL_STORAGE`, SMS/call-log permissions, foreground service types declared (API 34+: `foregroundServiceType`), exact alarm permissions, photo picker vs broad media permissions, notification permission (API 33+), predictive back, `android:enableOnBackInvokedCallback`, 16 KB page size support for native libs (state as check-item; confirm via linker flags/AGP version), account deletion path (Play requirement for apps with account creation: Needs Verification), COPPA/Families policy if applicable, ads ID usage (`AD_ID` permission declared when used).
- (2) Privacy (MASVS-PRIVACY-1..4): collects/transmits identifiers (IMEI/serial/MAC/Android ID) -> restricted; location/contacts/mic/camera access without purpose strings/runtime consent flow; analytics before consent; PII in logs/URLs; no user-facing data deletion/export path (Needs Verification).
